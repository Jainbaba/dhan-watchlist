# TradeBaba Handoff

## Current state

The project is a Chrome MV3 extension for Dhan, renamed **TradeBaba**.

- Native browser side panel; no fixed overlay.
- Left side: local prototype watchlist (Reliance, TCS, Infosys, HDFC Bank).
- Clicking a row switches the active Dhan chart via the validated
  `activeChart().setSymbol(...)` bridge.
- Right side: Screener-derived financial UI follows the chart identity.
- User confirmed the sample watchlist/chart switching works.
- Existing Dhan watchlists are not mutated by prototype clicks.

Sections, backup and search source (2026-09-09):

- Sections inside a list: a `Section` toolbar button adds a divider, dividers
  rename inline, collapse/expand, and removing one keeps its symbols. A row's
  `⋯` menu gains "Move to section" (Top, or any divider). List counts count
  symbols, never dividers. Search flattens sections while filtering.
- `chrome.storage.sync` backup: debounced 1.5s after any change, restored on
  open only when the stored copy's `updatedAt` is newer than this device's.
  Both directions verified. NOTE: Brave keeps extension storage.sync on-device,
  so on Brave this is a durable backup, not cross-device sync.
- Symbol search now asks the page's TradingView datafeed `searchSymbols()`
  first, which is what Dhan's own search box uses and returns a ranked list;
  `ScanWatchlist` stays the fallback and returns the single resolver hit. That
  is why the dropdown showed one row. UNVERIFIED against the live datafeed.

Backup, ordering and sorting (2026-09-09):

- GitHub gist backup. The worker owns it: `pushBackup`/`pullBackup` in
  `background.js` read the token from `chrome.storage.local`, so it never rides
  in a message, a page, or a content script, and only ever goes to
  api.github.com. Settings gains a "Watchlist backup" card - paste a token with
  the Gists scope, Back up now, Restore from gist (inline confirm), Forget
  token. Pushes happen automatically 5s after any change; restore stays manual
  so a stale gist can never overwrite this device on its own. The gist is
  secret, not private: anyone with the URL can read it.
- Drag to reorder symbols, plus Alt+ArrowUp/Down on a focused row. The order
  lives in the list's `items`, so it persists and backs up with everything else.
- A column header row sorts by Symbol, Last, Chg or Chg% (no Name column: for
  most scrips the row's ticker is what you scan, and a name that only repeats
  the ticker is not rendered as a second line): click cycles
  ascending -> descending -> your own order, the choice is stored in
  `model.sort`, sorting happens inside each section, rows with no quote sort
  last, and dragging is disabled while a sort is active.

Quote pipeline and drag fixes (2026-09-10):

- Live ticks. `main.js` subscribes through the page datafeed's `subscribeQuotes`
  and batches ticks once a second; `bridge.js` broadcasts them as `quoteTick`
  and the panel repaints the cells in place. The 10s `getQuotes` poll is now
  only the fallback for a feed with no streaming.
- Prices at open. A first `getQuotes` failure means "the page has not built its
  datafeed yet", so the panel retries five times at 2s before showing the error,
  and refreshes again when Screener data lands. That is why prices used to
  appear only after a click forced a redraw.
- Screener fallback: the charted company's page is already fetched, so its
  Current Price fills that one row's Last when nothing live answered. It is
  labelled "From Screener, delayed", rendered muted/italic, and never overwrites
  a live quote. Screener has no tick or change field - do not add one.
- Drag was broken for a real reason: the row's drag source was the row div, but
  Chrome will not start an ancestor drag from a mousedown on a button, and the
  row is a button. Rows and section dividers now carry an explicit handle. A
  divider drags its whole group (divider plus symbols up to the next divider).
- `defaults()` seeded `sort: "custom"`, a truthy string, so a fresh install read
  as "sorted" and disabled dragging. It seeds `null` now.

Opening on Dhan, and drag while sorted (2026-09-10):

- Chrome refuses `sidePanel.open()` outside a user gesture, so there is no true
  "open on navigation". What exists instead: `chrome.tabs.onUpdated` makes
  TradeBaba that tab's side panel on tv.dhan.co (and disables it elsewhere), and
  the content script forwards the page's FIRST pointerdown/keydown as the
  gesture that opens it. Also wired: Alt+D (`_execute_action`), the toolbar
  button, and an "Open TradeBaba" page context-menu item. Settings has an
  "Open automatically on tv.dhan.co" toggle (`tradebaba:autoOpen`, default on).
  `contextMenus` permission and a `commands` block were added to the manifest.
- Dragging while a sort is active no longer refuses. `commitSortedOrder()`
  freezes the visible order as the list's own order, clears the sort, then
  applies the move, so rows never jump under the pointer. Dragging while
  searching works too: the insert index is computed against the full list, so
  hidden neighbours are respected. Colour lists stay non-draggable - their order
  comes from the flags, not from the list.

Analysis pane sections (2026-09-10):

- Growth is now parsed and shown. Screener keeps it as `table.ranges-table`
  blocks inside `#profit-loss` (Compounded Sales/Profit Growth, Stock Price
  CAGR, Return on Equity); `parse()` picks all of them up and the Growth card
  renders each with its own heading. A company with none says so.
- Every card has a collapse toggle and, except Key Ratios, a drag handle. Key
  Ratios is pinned first and is not a drop target. Order and collapsed state
  live in `tradebaba:sections` and survive a reload. A collapsed card builds no
  body, so folding a table away also stops rendering it. A section added in a
  later version appends at the end rather than disappearing.

Whole-row dragging (2026-09-10):

- The `⠿` handles are gone from the watchlist. A row or divider is draggable
  across its entire area, including the ticker and the company name. The reason
  the handle existed at all was that Chrome will not start an ancestor drag from
  a mousedown on a form control, so the row label is now a div with
  `role="button"` and `tabindex=0` instead of a `<button>`; Enter and Space
  still activate it, and a drag suppresses the click that would follow, so
  clicking to change the chart is unaffected. `select()` marks a busy row with a
  class rather than the `disabled` property a div does not have.
- The analysis cards work the same way: no icon, the whole card drags,
  heading and contents together. Key Ratios stays pinned and is neither
  draggable nor a drop target. Data tables set `draggable=false`, so the
  numbers inside them stay selectable and scrollable while the rest of the
  card is the drag surface. Card headings are divs with `role="button"` for
  the same reason the rows are.

Keyboard shortcuts on the chart (2026-09-10):

- Alt+A adds the charted stock to the active watchlist; Alt+1 flags it Red,
  Alt+2 Green. Orange/Yellow/Blue/clear-flag are declared but unbound - Chrome
  allows only four suggested keys per extension, so bind the rest at
  brave://extensions/shortcuts.
- Flow: the command fires in the worker, which asks the tab what is charted
  (`chart-symbol` relay reading `activeChart().symbol()`), validates the symbol
  against the chart-symbol shape, then hands the panel `{command, symbol, name}`
  - the panel owns the model, the worker cannot read its storage. A command is a
  user gesture, so the panel is opened first when closed, and the message is
  retried once after 800ms if nothing acknowledged it.
- Adding while a colour list is active is refused with a message rather than
  written somewhere else; flagging still works there. Duplicates are refused.

Divider dragging corrected (2026-09-10):

- A divider is a boundary, not a container. Dragging one now moves ONLY the
  divider; every symbol stays where it is, so dropping it between two rows just
  changes where the grouping starts. The earlier "carry the group" behaviour
  caused both reported bugs: moving a divider reshuffled the symbols that
  followed it, and a divider sitting at the top could never move at all,
  because it owned every row below it and so every drop target was inside its
  own block. `sectionBlock()` is gone.

- `syncAthList()` mirrors the repo's published list into a "6-Month Stocks"

ATH screener range (2026-09-10):

- `ath_watchlist.py` kept the 100cr market-cap floor (`market_cap_basic > 1e9`,
  which is 100 crore in rupees) - that was already correct. What was wrong for
  an inclusive range was the extra `high != High.All` filter: it dropped any
  stock whose current high equals its all-time high, so the top of the band was
  excluded. Removed. The band is now exactly `close between High.All*0.8 and
  High.All`, inclusive at both ends, and the threshold only moves the lower
  bound. Tests assert the filters by field rather than by list index.

Header (2026-09-10):

The ATH cron moved to 17:00 IST (11:30 UTC), retry 19:00 IST, so the range is

Settings interactions (2026-09-10):

- Shortcut rows are buttons: an unbound one reads "Set...", and clicking any row
  opens chrome://extensions/shortcuts via `chrome.tabs.create`. It cannot be a
  true inline capture - `chrome.commands` is read-only, only the browser can
  bind a key, so a key-capture box in the panel would bind nothing.
- Metric colours now has one <details> per section - Quarterly Results, Profit &
  Loss, Shareholding Pattern, each with its own count - instead of a single flat
  fold. All start closed.

Quote flicker on every list action (2026-09-10):

- Any mutation calls `renderWatchlist()`, which rebuilds the list DOM, so the
  Last/Chg cells were recreated as em-dashes and only refilled when the next
  snapshot or tick landed - the blank-then-return the user saw. `quoteData`
  already held the last value per symbol; `stockRow()` now paints from it as the
  cell is created, so a rebuild is invisible.
- While a stream is live and the symbol set has not changed, a redraw no longer
  re-subscribes or re-polls (`watching` key). Verified: prices identical in the
  same frame as the rebuild, and getQuotes/watchQuotes stayed at one call each.

Sorting flashed zeros, and the ATH list was empty (2026-09-10):

- Sorting reorders the symbol array, and the "same symbols" guard compared join
  order, so every sort looked like a new subscription: it resubscribed, and the
  feed's first partial quote paints zeros. The key is now order-insensitive -
  the watched SET is what matters. Verified: a sort reorders rows with no
  resubscribe (watchQuotes stayed at 1) and no blank frame.
- The ATH mirror was reading the wrong file. `ath_watchlist.py` publishes
  `ath-watchlist.json`; the sync called `fetchPublishedList()`, which fetches
  `watchlist.json` - a different list from build_list.py. Its symbols are also
  exchange-qualified ("NSE:FOO"), and the worker's name filter rejects the
  colon, so even the right file would have resolved to nothing. `fetchList(url)`
  now takes the URL, `source: "ath"` selects ATH_URL, and the exchange prefix is
  stripped before the names reach ScanWatchlist. The silent catch that hid all
  of this now reports the reason in the status line.

Scanner rewrite, sync removal, Dhan push (2026-09-10):

- The ATH list had never been published: `ath-watchlist.json` 404s on main, and
  the builder could not run at all. TradingView's scanner now rejects the old
  body (`markets`/`symbols` keys) AND any filter whose right operand is an
  expression, so `close between [High.All*0.8, High.All]` is dead. It asks for
  `High.All` as a COLUMN and applies the band in build(). Confirmed live: 2624
  NSE names above 100cr, 793 inside the 0-20% band, 14 sitting exactly at their
  high. 250 is our cap (Dhan's per-watchlist limit), not the match count, and it
  now keeps the names CLOSEST to their high instead of the alphabetically first;
  `matched_total` records the real number.
- The on-page sync UI and the repo-mirroring sync are gone from `main.js`:
  mountUI, buildPanel, the dead mountScreener renderer, syncFromRepo, the
  cross-tab lock, findTarget, describeWindow and their constants. ~370 lines.
  Their assertions came out of test.mjs with them.
- "To Dhan" pushes a local list into the Dhan watchlist OF THE SAME NAME: a
  window confirm first, then resolve via ScanWatchlist, clearWatch,
  AddMultipleStock. Capped at Dhan's 250. It does NOT create a watchlist - no
  create endpoint is verified from captured traffic, so a missing list is
  reported ("create it in Dhan first") rather than guessed at.
- The worker reloads open tv.dhan.co tabs on install/enable/update, since
  content scripts only attach on a page load.

Charted-row highlight and step-through (2026-09-10):

- `watchChartSymbol` already polled the chart every second; it now also
  broadcasts the FULL symbol (not the ticker the Screener lookup uses), which
  `bridge.js` forwards as `chartedSymbol`. The panel marks that row with a blue
  left bar by toggling a class, not by re-rendering, so the quote cells stay put.
- Space charts the next row and wraps at the end. It walks the rendered order,
  so sorting, filtering and sections are all respected. It is ignored while a
  text field has focus, and a row that handled Space itself wins.
- Space is reserved for "next" throughout the panel. It first looked broken -
  "just clicking again" - because focus sits on the row you clicked, and that
  row's own Space handler re-charted it and called preventDefault, which
  blocked the advance. Rows and dividers activate on Enter only now, and
  advancing moves focus to the new row so the next Space continues down.
- A `next-symbol` command does the same from the Dhan chart page, unbound by
  default (Chrome allows only four suggested keys). It carries no symbol, so
  `panelCommand` must handle it BEFORE the chart-symbol guard - that guard
  silently swallowed it in the first cut.
